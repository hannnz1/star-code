## 背景

Feature 002 只执行一批工具，结果回灌后的再次工具调用会被丢弃。Feature 003 引入受限 ReAct Agent Loop，使模型能够“观察 → 调用工具 → 查看结果 → 调整”，直到自然完成或触发安全停止条件。

## 目标

- 多步 ReAct 循环，不再丢弃续答工具调用。
- Agent 通过事件与 TUI 解耦。
- 连续只读工具并发，有副作用工具保持串行和原始顺序。
- 支持自然完成、迭代/调用上限、连续未知工具、取消和协议错误。
- 汇总每轮与会话 Token 用量、展示迭代进度。
- `/plan` 仅提供只读工具；`/do` 恢复全工具并执行最近计划。

## 安全修订

原稿要求取消权限与路径限制，这会倒退 Feature 002 的安全基线。本功能继续遵守：

- 文件工具只能访问启动工作区，拒绝绝对路径、`..` 和符号链接逃逸。
- 写入/编辑要求 `STAR_CODE_ALLOW_WRITES=true`。
- Bash 要求 `STAR_CODE_ALLOW_BASH=true`，并受超时约束；它仍不是完整 OS 沙箱。
- 迭代上限 10、工具调用上限 50、连续未知工具阈值 2，均为 V1 内置常量。

## 功能需求

- F1：每轮流式请求后，若含工具调用则执行、回灌并继续；无工具调用则自然完成。
- F2：支持自然完成、迭代上限、工具调用上限、取消、连续未知工具和流错误停止。
- F3：输出迭代开始、文本增量、工具开始、工具结束、用量、完成、取消和错误事件。
- F4：协议层同时实时发送正文增量并收集完整正文、工具调用和用量。
- F5：连续只读调用组成并发批；副作用调用单独串行；结果始终按模型原顺序回灌。
- F6：每轮 assistant 工具调用及对应结果都进入本次协议请求链；提前终止时不再产生悬空工具调用。
- F7：取消令牌阻止后续迭代并尽力中断工具任务；空闲 Ctrl+C 仍退出程序。
- F8：提取每轮输入/输出 Token，并累加会话用量。
- F9：TUI 展示当前迭代和会话累计用量。
- F10：`/plan` 切换只读工具和计划提示；`/do` 恢复全工具并自动触发执行提示。
- F11：OpenAI Responses 与 Anthropic Messages 使用相同 Agent Loop。

## 非功能需求

- N1：Bash 默认 30 秒超时；其他工具使用既有体量和路径限制。
- N2：Agent 提供异步入口，工具与网络工作不占用 TUI 事件线程。
- N3：事件按真实发生顺序输出；并发结果按调用原顺序发布和回灌。
- N4：工具结果保持既有 50,000 字符、200 条结果等上限。
- N5：取消后不再开始新迭代，虚拟线程执行器必须关闭。
- N6：并发批不共享可变结果容器，汇总阶段按索引组装。
- N7：API Key 继续脱敏。
- N8：`gradlew test shadowJar --warning-mode all` 通过且无弃用警告。

## 不做的事

- 完整 OS 沙箱、逐次权限弹窗、上下文压缩、会话持久化、子 Agent、MCP、计划审批和多模态。
- 跨批重排；只有连续只读批内部并行。
- 工具结果流式输出。

## 验收标准

- AC1：Fake LLM 完成 Read → Edit → Read → 最终文本，无需用户催促。
- AC2：无工具调用立即自然结束。
- AC3：重复调用达到迭代/工具上限时停止。
- AC4：连续两轮只请求未知工具时停止。
- AC5：Provider 错误作为 Agent 错误事件返回，会话可继续。
- AC6：事件包含迭代、文本、工具开始/结束、用量和完成/错误。
- AC7：工具 JSON 分片仍由两个协议正确收集。
- AC8：连续只读工具并发、副作用工具串行，结果保持原始顺序。
- AC9：本次循环的每批调用和结果均出现在下一次协议请求中。
- AC10：取消后不开始下一迭代并返回取消状态。
- AC11：用量跨迭代累加。
- AC12：TUI 显示当前迭代。
- AC13：Plan Mode 只暴露 Read/Glob/Search；`/do` 恢复六工具并触发执行。
- AC14：双协议 Mock HTTP 多步回灌测试通过。
