# 上下文管理 Spec

> 状态：IMPLEMENTED（两层压缩、结构化边界与 replacement 恢复已实现）  
> Feature：008  
> 全局契约：[`../architecture-contracts.md`](../architecture-contracts.md)

## 背景与目标

长会话会持续扩大请求上下文，尤其是 `read_file`、`bash`、`search_text` 和 MCP 工具的长结果。系统采用两层防御：先把大工具结果稳定落盘并以预览替换，再在上下文接近窗口时用无工具 LLM 请求生成摘要。

- G1：单进程长会话不因上下文持续膨胀而直接中断。
- G2：替换决策和字符串稳定，尽量保持 prompt cache 前缀。
- G3：完整工具结果仍可通过文件路径重读。
- G4：自动、手动、紧急压缩复用同一摘要核心路径。
- G5：Provider 上下文窗口由配置驱动。

## 功能需求

- F1：单条工具结果超过 50,000 UTF-8 字节时写入会话 `tool-results/<tool-use-id>`，上下文改为稳定预览。
- F2：同一工具结果消息中，未被 F1 替换的正文合计超过 200,000 UTF-8 字节时，按字节数从大到小继续落盘，直到剩余值不超过阈值。
- F3：预览包含原字节数、前 20 行且最多 2,048 UTF-8 字节的头部、落盘路径和重读提示。
- F4：落盘、改写、记录决定按固定顺序完成；失败时保留原文且不记录已见状态，下次允许重试。
- F5：同一 tool-use ID 的保留/替换决定在会话内冻结；替换字符串逐字节稳定。
- F6：替换记录追加到会话持久化账本；`/resume` 时重建已见集合和 replacement 映射，满足全局契约 A4。
- F7：每次 Provider 请求组装前执行第一层检查；它不调用 LLM。
- F8：估算 token 达到 `context_window - 20,000 - 13,000` 时，在下一次普通请求前自动摘要。
- F9：摘要请求不携带工具，只保存 `<summary>`；摘要覆盖请求意图、技术概念、文件代码、错误修复、解决过程、用户原话、待办、当前工作和下一步。
- F10：摘要后从尾部保留至少 10,000 估算 token 且至少 5 条结构化消息；不得切开 tool call/result 配对。
- F11：恢复段包含最近 5 个成功读取文件、当轮实际工具定义和“需要原文就重读，不要靠摘要猜测”的固定提醒。
- F12：usage 锚点使用最近一次 Provider usage 替换更新；新增文本按 3.5 字符/token 估算。
- F13：`/compact` 无条件触发摘要，不作为普通用户消息发送。
- F14：普通请求遇到 `prompt_too_long` 时执行一次紧急压缩并仅重试一次。
- F15：摘要自身过长时按最旧“用户提交及其 assistant/tool 往返”消息组逐步丢弃；不得用固定两条消息模拟一组。
- F16：自动摘要连续失败 3 次后熔断；手动和紧急压缩绕过熔断。
- F17：Provider 支持 `context_window`；默认 Anthropic 200,000、OpenAI 128,000。
- F18：会话 ID 和目录由 ch09 `SessionContext` 统一提供；本章不得自行生成另一种 ID。

## 非功能需求

- N1：账本、文件追踪、usage 锚点和熔断状态线程安全。
- N2：落盘失败降级为保留原文，摘要失败不使主进程崩溃。
- N3：核心预算、截断、估算、分组和恢复算法可离线测试。
- N4：日志不得输出 API Key、Authorization、Cookie 或工具结果中的已知凭据。
- N5：不触发压缩时不得改变已有 Agent Loop、权限、MCP 或 Provider 行为。

## 不做的事

- 不集成精确 tokenizer。
- 不做跨会话语义检索。
- 不自动清理会话工具结果目录。
- 不把内部阈值开放为配置；仅开放 `context_window`。

## 验收标准

- AC1：60,000 UTF-8 字节结果被稳定预览替换，完整文件可重读。
- AC2：3×80,000 字节批次以最小替换数回落到 200,000 字节以内。
- AC3：同一 ID 重复组装不重写文件，replacement UTF-8 字节完全相同。
- AC4：落盘失败的 ID 不进入已见集合，下一次可以重试。
- AC5：自动阈值边界前不触发、跨过后在普通请求前触发。
- AC6：摘要请求的工具定义为空，且只采用 `<summary>` 内容。
- AC7：近期消息同时满足 token 和条数下界，并保持 tool call/result 闭合。
- AC8：恢复段文件、工具和边界提醒完整；工具定义与紧随其后的请求使用同一列表。
- AC9：手动 `/compact` 低于阈值仍执行，成功后报告前后估算值。
- AC10：普通请求首次 PTL 经紧急压缩重试一次；再次 PTL 不循环压缩。
- AC11：摘要 PTL 按真实消息组丢弃并有终止条件。
- AC12：连续三次自动失败后熔断，成功一次清零；手动/紧急不计入熔断。
- AC13：恢复会话后 replacement 账本重建，同一 ID 不产生新预览版本。
- AC14：完整测试与 Shadow JAR 构建通过，既有 Agent Loop、MCP 和权限测试无回归。
