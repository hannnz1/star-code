# 系统提示工程化 Spec

## 背景

Feature 003 已实现 Agent Loop，但系统提示仍是固定字符串，稳定指令、动态环境和模式提醒没有分层，也无法观测 Provider 的提示缓存命中。本章将系统提示模块化，并把稳定前缀、动态环境和临时提醒分别放入适合的请求通道。

## 目标与功能需求

- F1：七个固定职责模块包含名称、优先级和内容，按优先级降序、空行分隔；预留自定义指令、Skill、长期记忆三个空槽，空内容跳过。
- F2：动态环境包含工作目录、平台、日期、Git 状态（可获取时）、版本和模型，并与稳定提示分块。
- F3：Anthropic 对稳定 system 与工具定义设置显式缓存断点；OpenAI 保持稳定 instructions/tools 请求前缀。
- F4：解析输入、输出、缓存创建和缓存读取 token；缺失字段按零处理。
- F5：系统提示与工具描述同时强化“优先专用工具”和“编辑前先读”。
- F6：动态 reminder 使用 `<system-reminder>`，只在构造请求时附加，不写入 Conversation。
- F7：Plan Mode 首轮和每四轮注入完整提醒，其余轮次注入精简提醒，且仍只开放只读工具。
- F8：OpenAI 与 Anthropic 使用相同稳定模块、环境字段和 reminder 策略。

## 非功能需求

- N1：稳定块和工具顺序跨轮确定不变。
- N2：不退化既有 Agent Loop、取消、工具编排和历史行为。
- N3：动态 reminder 不制造悬空工具调用或持久化历史污染。
- N4：Git 环境采集限制为 500ms，失败时省略该字段。
- N5：环境中不读取密钥或任意环境变量。
- N6：缓存字段缺失时安全返回零。
- N7：以仓库真实规范 `gradlew test shadowJar --warning-mode all` 验收。
- N8：新增模块不修改装配算法。

## 不做的事

不加载项目指令文件，不接入真实 Skill/MCP/长期记忆，不做历史增量缓存、TTL 配置、运行时热加载、缓存状态栏、多模态或流式工具结果。

## 验收标准

- AC1/AC2/AC5：模块顺序、空槽和确定性由单元测试验证。
- AC3/AC10：两种协议请求包含稳定提示和独立动态环境块。
- AC4/AC6：缓存用量字段解析正确，缺失时为零。
- AC7：系统模块和工具描述均包含两条关键约定。
- AC8/AC9：reminder 标签、完整/精简节奏及 Plan 只读工具正确。
- AC11/AC12：既有 Agent Loop 回归、取消和历史行为继续通过。
- AC13：非 Git 环境采集快速降级。
- AC14：Gradle 测试和可执行 JAR 构建通过，输出不泄漏 API Key。
