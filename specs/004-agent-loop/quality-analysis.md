# ch04 Spec 质量分析

## 结论

用户原稿的产品目标、ReAct 流程、并发策略和验收场景都很清晰，原始质量约为 **8.3/10**。完成本次校正后，作为 Star Code 的实现合同约为 **9.2/10**。

## 原稿优点

1. 清楚描述了从单批工具闭环到自主多轮 Agent 的价值变化。
2. F1–F11 基本覆盖主循环、事件、流式收集、并发、取消、用量、Plan Mode 和跨协议。
3. “连续只读并发、有副作用串行、结果保序”是可执行且安全的并发规则。
4. 对提前终止后的历史合法性有明确要求，避免 Provider 400 和会话损坏。
5. 验收标准大多可以通过 Fake Provider 和 Fake Tool 离线验证。

## 查漏补缺与校正

### 1. 章节编号与现有目录冲突

原稿称 ch04，但仓库早期把 Agent Loop 放在 `003-agent-loop`。已建立独立 `004-agent-loop`，并将旧目录标记为历史版本。

### 2. 缺少工具调用总量上限

原稿只强调迭代上限，但当前实现还有 50 次工具调用上限。新 Spec 把 `TOOL_LIMIT` 纳入正式停止状态和验收，避免单次模型回复塞入大量工具调用绕过迭代上限。

### 3. 空响应没有定义

“无工具调用即自然完成”会把空文本、空工具的异常响应当成成功。新 Spec 要求可辨识的空响应错误；当前实现尚未满足。

### 4. 取消语义不够具体

仅设置 cancel flag 不代表正在进行的 HTTP、审批、命令和并发任务会停止。新 Spec 明确了四类需要传播取消的对象以及取消后的结果配对要求。

### 5. 工具上限可能制造悬空持久化事件

当前 UI 在 `ModelTurnCompleted` 时就持久化 assistant tool calls，而 Loop 随后才检查工具总量；触顶时没有对应 tool results。内存 Conversation 不提交失败 run，因此下一次普通请求仍安全，但 JSONL 会留下需恢复器截断的孤立调用。新 Spec 要求停止路径主动补结果。

### 6. “所有工具 30 秒超时”与实现不一致

当前 Bash 和 MCP 有超时，本地文件工具没有统一执行器级 deadline。新 Spec 保留这一目标，并在 Tasks 中列为待实现，而不是假定已经由 ch03 提供。

### 7. 安全边界表述会造成倒退

原稿“不做路径白名单、不限制工作目录”的表述与项目已有工作区保护冲突，也不应为了复刻章节历史而取消安全基线。新 Spec 改为“本章不新增权限系统，但不得移除既有工作区安全”。

### 8. 构建规范不匹配

项目使用 Java 21 + Gradle，没有 Maven Spotless 或 `CLAUDE.md`。验收命令已改为仓库实际可运行的 Gradle 命令。

### 9. 跨协议验收需要分层

单纯检查两个解析器能拼工具参数，不等于两个协议都跑通完整 Loop。新 AC15 要求“适配器解析测试 + Loop 集成测试 + 受控人工证据”至少覆盖其一并保留证据。

## 仍建议补充的工程指标

- 取消响应时间目标，例如本地任务 1 秒内停止、HTTP 在请求超时前可主动取消。
- 并发批最大规模，避免模型一次返回数百个只读调用时创建过多虚拟线程。
- AgentEvent 是否需要序号/时间戳；如果未来用于持久审计，应该提前定义。
- 工具超时后对子进程树、HTTP 调用和本地线程的具体关闭语义。
