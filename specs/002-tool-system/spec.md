# 工具系统 Spec

## 背景

Feature 001 已打通“用户 ↔ LLM”的多协议流式对话闭环，但模型尚不能读取、修改项目或执行命令。Feature 002 引入工具抽象、六个核心工具、流式工具调用解析、结果回灌与一次续答，使 Star Code 从聊天客户端演进为能够完成单批工具工作的 Agent。

## 目标

- 提供协议无关的工具定义、调用、结果和注册中心。
- 实现 `read_file`、`write_file`、`edit_file`、`bash`、`glob`、`search_text`。
- OpenAI Responses 与 Anthropic Messages 均支持工具定义、工具调用和结果回灌。
- 工具失败作为结构化结果返回模型，不终止会话。
- 一次模型回复可请求多个独立工具；顺序执行后只续答一次。
- TUI 显示 Claude Code 风格的工具调用行和结果摘要。

## 安全修订

原始草案把权限、沙箱和路径白名单全部排除，却同时开放覆盖文件与任意命令，风险不可接受。Feature 002 采用以下最低安全边界：

- 文件工具只允许访问程序启动工作目录内的真实路径，拒绝 `..`、绝对路径和符号链接逃逸。
- 命令固定以启动工作目录为当前目录，受超时与输出上限约束。
- 读取、Glob、搜索默认启用；写入/编辑要求 `STAR_CODE_ALLOW_WRITES=true`，命令要求 `STAR_CODE_ALLOW_BASH=true`。
- 本期尚无逐次权限确认，因此使用者应只在可恢复、受版本控制的项目中启用写入和命令工具。

## 功能需求

- F1：统一 `ToolDefinition`、`ToolCall`、`ToolResult`、`Tool` 和 `ToolRegistry`；协议适配器负责转为各 API 格式。
- F2：实现六个工具；读取带行号，写入可创建父目录，编辑要求旧文本唯一匹配，命令返回 stdout/stderr/exit code，Glob 返回相对路径，搜索返回文件/行/内容。
- F3：请求携带全部工具定义，并使用 Agent system prompt。
- F4：流式组装调用 ID、工具名和 JSON 参数；正文、推理与工具调用分离。
- F5：同一批调用顺序执行，每个调用均返回结构化成功或错误结果。
- F6：将第一批调用及结果按协议格式回灌，只续答一次；续答再次请求工具时不执行并显示步骤上限提示。
- F7：两个协议向上层暴露相同的模型轮次接口。
- F8：TUI 显示 `● Tool(key argument)` 和截断后的结果摘要。
- F9：未知工具、参数错误、路径越界、I/O、超时、非零退出及无结果均不得导致未捕获异常。

## 非功能需求

- N1：Bash 默认 30 秒超时，超时后终止进程及其后代。
- N2：工具执行不泄漏 API Key；输出进入模型前受长度限制。
- N3：单文件最多 1 MiB，工具文本结果最多 50,000 字符，Glob/搜索最多 200 条。
- N4：默认自动化测试不访问外部网络，也不使用真实 API Key。

## 不做的事

- 多批连环 Agent Loop。
- 工具调用持久化、MCP、自定义工具、并行执行和工具折叠 UI。
- 完整 OS 沙箱与逐次权限审批；这些必须在扩大工具权限前作为后续 Feature 实现。

## 验收标准

- AC1：注册中心可列出六个工具、按名查找并导出协议无关定义。
- AC2：读取存在/不存在文件分别返回带行号内容/结构化错误。
- AC3：写入可创建嵌套文件并覆盖内容，路径越界被拒绝。
- AC4：编辑在匹配 1、0、多个时分别成功、返回 NOT_FOUND、返回 AMBIGUOUS。
- AC5：命令返回输出和退出码；超时被终止并返回 TIMEOUT。
- AC6：Glob 与搜索返回相对路径及命中行，结果受数量上限控制。
- AC7：两个协议均可组装含 ID、名称、参数的流式工具调用。
- AC8：读取文件并总结只执行一批工具，回灌后得到最终文本。
- AC9：续答再次请求工具时不执行，显示单轮上限错误并保持会话可用。
- AC10：工具行和结果摘要可见，长结果被截断。
- AC11：工具失败后程序可继续接受下一条消息。
