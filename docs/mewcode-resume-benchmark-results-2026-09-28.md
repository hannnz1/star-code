# Mewcode / MUSE Python 项目介绍 Benchmark 实测报告（2026-09-28）

本报告按 [Benchmark 计划](mewcode-resume-benchmark-plan.md) 对简历表述逐项判定。结论：**当前不能把项目介绍中的 85%、8 小时、30→5、17%→100%、约 60% 和 OS 内核隔离写成已验证的 Python 版成绩；Java 完全替代版也仍未正式验收。** 部分功能与短程压力试验已有可复核证据，见下表。

## M 组详细指标与口径

正式运行使用冻结的 100 个本地合成 MCP 工具、10 种任务模板各 3 个不同实体编号，形成 30 个任务；每轮重新编号、固定种子打乱顺序，FULL/LAZY 顺序为 `FULL_LAZY`、`LAZY_FULL`、`FULL_LAZY`。每题隔离工作区与状态库，真实调用配置中的 Luna 模型及本地 HTTP MCP 服务。FULL 从**首个请求**提供 100 工具定义；LAZY 走生产的发现、搜索、加载、调用流程。每次远程调用必须精确命中目标工具和实体 ID，且回答包含预期值。

| 指标 | FULL | LAZY | 降幅 |
| --- | ---: | ---: | ---: |
| 正确完成 | 90/90 | 90/90 | 无质量下降（本夹具） |
| 首次请求 MCP 定义 Token | 775,080 | 32,130 | **95.85%** |
| 全会话 MCP 定义、目录索引、搜索结果及加载 schema Token | 3,490,243 | 737,217 | **78.88%** |
| 实际 API 输入 Token | 2,691,875 | 1,972,734 | **26.72%** |
| 实际 API 输出 Token | 9,465 | 11,655 | LAZY 增加 23.1% |
| 每题平均墙钟秒 | 11.42 | 10.01 | 描述性数据，非速度宣传结论 |

会话描述使用 `tiktoken/o200k_base` 对紧凑 JSON 计数，包含重复发给模型的 MCP 定义与工具发现/搜索/加载消息；不等同 API 账单 Token。各轮会话降幅分别为 **78.69%、78.90%、79.04%**。95% 区间按 90 个配对、固定种子 10,000 次 bootstrap 的百分位数计算，只描述本夹具波动。30 题来自 10 种语义模板，不能外推到复杂真实 MCP 服务。中止的旧 FULL 测量器首请求未暴露目录，14 次结果只计费用，不计正式指标。

本次计算的正式 M 组标准单价估算 **$0.477**；这是全量 API 用量费用，不是“描述 Token 节省”。逐题与汇总见 `work/resume-benchmark/rc8-baseline/mcp-formal-v2-repeat-{1,2,3}/description-tokens.json` 和 `mcp-formal-v2-aggregate.json`。

## 复核与剩余验收

归因修正：先前报告将“子任务数量为 0”描述为 Luna 没有派发子任务，这一推断不成立。三个案例的 `*-calls.json` 均记录了真实 `spawn_worktree` 请求及 Git 创建错误；需先诊断运行时/Windows 工作树环境，再用同一模型重跑，才能评价协作质量。

Benchmark 测量器的新增单测 **12/12 通过**，Ruff 检查通过；本次针对性产品回归 **186/186 通过**（本机临时目录权限问题重跑后通过），包含记忆用例的单测文件另核对 **10/10 通过**，还有符号链接单测 1/1 通过。既有 RC8 工程回归是 **974 通过、2 跳过、3 项分开通过**，见 `dist/rc-c27b83b/RELEASE_STATUS.md`。本次未重新跑整套 RC8，也未重新构建发布 wheel。

仍需外部条件或长时间试验：独立干净 Windows 机器上的真实 P01 和完整业务复跑、60 行人工审核及双人复核、官方 SWE-bench-Live Docker 环境和足够磁盘、C8 的 3 个真实长会话、30 会话前端弹窗对照、旧新版同事实集比较、OS 沙箱实现/攻击验证，以及 12+4 任务的单/多 Agent 配对。未完成项目不得在简历或发布说明中写为已验证成绩。当前推荐表述是：“Python 核心 Coding Agent，支持 MCP 按需发现/加载及短程长上下文保留；在 100 工具合成夹具上，90 对任务全部正确，首次工具定义 Token 减少 95.85%，全会话描述 Token 减少 78.88%。”
