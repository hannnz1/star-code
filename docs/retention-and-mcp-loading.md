# 长上下文事实保留与 MCP 按需加载

日期：2026-09-27。实现位于当前 Python 工作区；沿用原 StarCode 模型配置，没有修改原 Java 工程。

## 已实现

长上下文压缩现在保留有来源角色和哈希的原文摘录，以及完整的近期工具调用/结果对。对于用户明确给出的 JSON 标量字段，生成“最新值”视图，较新记录覆盖较旧记录；工具输出不能写入这个用户状态视图。重复给出旧值视为一次新的更正。所有记录都只是引用数据，不能改变审批或工具权限，不生成未经证据支持的模型摘要。

自动压缩前的会话检查点、手动压缩前的存档，可由只读 `recall_history` 检索。只查询当前任务，不接受任意任务 ID，不重放工具动作。摘录有容量限制；检索最多扫描最近 100 个检查点，返回最多 8 段、每段最多 1000 字符，使用区分大小写的字面查询。不能承诺任意长度历史全部常驻模型输入。

MCP 流程为：`mcp_discover`（批准后连接、保存完整目录但只返回短索引）→ `mcp_search`（本地检索，最多 5 个匹配）→ `mcp_load`（每次最多加载 5 个 schema）→ `mcp_call`（再次独立审批后执行）。加载的定义进入 `mcp_call` 参数 schema，未选中的定义不会通过目录元数据进入模型输入。

完整目录保存在应用状态中，模型投影剔除私有目录元数据。每个任务最多激活 10 个工具；配置指纹变化后旧目录与加载状态失效。JSON-pointer 本地引用在嵌套 schema 中重新定位，参数仍由实际 schema 校验。兼容已有通用 `mcp_call` 路径，但加载不产生执行授权。这里优化的是模型侧暴露，MCP 协议连接仍完整发现服务目录。

初始 schema 局部降幅为 93.50%。本次用的是原“选工具”夹具经 FastMCP 提供的 100 工具，不是原 Java 7377→2420 的内置工具复制夹具；不能直接比较两个百分比，更不能称总费用降低 93.50%。本次每题实际模型请求和 Token 用量见证据，不以 schema 指标代替账单。

第一次真实上下文探针结果为 11/11、17/17、22/23，错误是超时值引用了旧记录。随后增加最新显式用户值视图，第二次及最终修订后的第三次均达到三检查点全对。首次失败记录保留，不合并挑选最佳字段。
