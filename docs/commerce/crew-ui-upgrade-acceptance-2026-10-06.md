## 实施内容

| 阶段 | 已实现内容 | 自动验证 |
|---|---|---|
| 1 导航与首页 | 单一主导航、店铺切换、默认商家概览、待处理事项、建站/上新入口、独立开发空间、设置内记忆入口 | 默认入口、无重复侧栏、任务地址刷新/返回、跨店铺选择 |
| 2 业务流程 | 建站和上新步骤视图，品牌/政策编辑，结构草稿与商品准备，计划/审查入口，项目版本变化后重新校验 | 商品/图片校验、资料恢复、过期状态、输入恢复与项目隔离 |
| 3 任务与审查 | 看板/列表切换、业务目标与下一步、完成情况、折叠技术编号与版本、沿用成果审查与发布控件 | 原代码审查/整合、审批、未知回执、停止后续发布步骤、键盘切换 |
| 4 店长助手 | 项目及页面上下文、商品批次、请求上限、真实计划草稿 API、预计角色流程、打开草稿明确启动 | 打开/切换无写请求；保存仅写 task-drafts；刷新保留目标/工作流/预算，不新增模型调用 |
| 5 适配与验收 | 中英文、桌面/平板/手机、可见文字导航、原生焦点约束弹窗、会话草稿、空/错/加载状态 | 1440/1280/900/390/360px 新流程；原页面还有 768px；构建与语言合同检查 |

会话草稿按项目及版本隔离，包含品牌、商品 CSV、店长完整表单和独立的新团队任务表单。保存/启动成功后清理对应的新任务临时输入；已保存任务继续使用服务端记录。浏览器会话草稿不是权限、批准或业务事实的权威来源。

店长面板采用“准备计划 → 审查草稿 → 明确启动”的交互，保存时显示后端固定的预计角色流程；真正的模型执行使用原团队工作流和 StarCode 模型配置。

## 人工体验入口

### 工作目录入口简化（2026-10-06）

移除开发空间输入框内的工作区下拉框。标题下只读展示实际当前目录，并提示从设置的工作区管理切换；原工作区管理及任务 workspace_id 绑定保留。浏览器用例覆盖通过设置切换目录、实际路径更新、任务输入保留与390px长路径无溢出。截图：`work/crew-ui-upgrade-20261006/developer-workspace-390-zh.png`。

前端构建通过，工作区切换、模式提示、原编程提交、中英文与共享主题相关浏览器回归 10 项通过（`work/crew-workspace-entry-final.xml`）。本机预览已确认返回最新构建。

### 开发空间模式提示补齐（2026-10-06）

四种模式新增动态输入提示和能力说明，模式按钮用勾选及 `aria-pressed` 明确当前选择。“开始任务”替代仅图标提交；模式切换不提交任务、不产生模型调用，并保留原输入。“填入示例”仅在输入为空时可用，已有输入需先清空；下方快捷卡片同样不覆盖已有内容。勾选团队协作后显示分工及汇总检查说明。新增文案与示例支持中英文，用户输入保持原文。

新增浏览器用例验证模式说明、输入保留、示例保护、语言切换、390px 无页面溢出和零写请求；另沿用原编程任务提交验证其 `scenario='coding'`。手机截图：`work/crew-ui-upgrade-20261006/developer-guidance-390-en.png`。

最终前端构建通过；模式提示、商家/独立编程、中英文与共享主题相关浏览器回归 9 项通过（`work/crew-mode-guidance-final.xml`）。本机 8876 预览已返回最新构建文件。

### 店铺管理补齐（2026-10-06）

设置 → 店铺管理新增归档、恢复和永久删除。归档店铺从日常切换列表隐藏，仍可从设置恢复。永久删除要求输入完整店铺名称，并校验当前项目版本；仅事务删除 Crew 的商家项目、计划、商品资料、商家审批及相关业务记录。保留远程网站、工作区文件和独立开发任务日志；清理当前浏览器对应项目的会话表单缓存。

后端阻止以下移除条件：未结束的关联任务及子任务、未核对工具调用、排队草稿、运行中的模型/验证/本地应用任务、未知或部分发布结果，以及尚未清理的预览环境。归档项目不能继续通过普通商家 API 修改；恢复后版本递增，旧版本请求不能继续使用。

验证：相关回归 58 项通过（`work/crew-project-lifecycle-regression.xml`）；缓存清理后的 2 项浏览器复测通过（`work/crew-project-lifecycle-final.xml`）；归档 API 与任务保护加强后的 19 项后端复测通过（`work/crew-project-lifecycle-backend-final.xml`）。这些复测存在重叠，不累计为独立用例。前端构建及生成 API 类型检查通过。使用隔离测试数据，没有删除用户现有店铺。

独立审查发现旧 `verification_request` 为任务编号指针而非 JSON，已先用失败用例复现再修复。最终相关项目/验证 API、删除保护和浏览器复测 25 项通过（`work/crew-project-lifecycle-review-final.xml`）；无剩余重要或严重审查问题。

## 建站结构草稿去重与编辑修复（2026-10-06）

原因：生成按钮每次使用新的请求 ID；列表同时遍历独立草稿和团队工作流方案，造成相同七类页面反复出现。此前没有草稿编辑接口。

修复：同一项目当前版本生成时复用最新有效独立草稿（事务内查找），保留历史记录。一份当前草稿提供页面标题、英文路径、导航展示及名称编辑；旧草稿折叠只读，团队方案不再混入草稿列表。保存校验项目/方案版本、七类页面及唯一 slug、非空且指向真实页面的导航；商品详情模板不能直接加入页面导航。政策、运输、付款及验收状态保持服务端控制。项目资料改变后旧草稿失效，新建团队建站工作流使用当前保存结构，重新计算店铺设置要求，不改变已有团队任务。

防止初始 GET 旧响应覆盖生成/保存结果：列表加载完成前禁用操作，跨项目响应不回写。手机版编辑表单单列。

验证：93 项相关回归通过（work/crew-blueprint-fix.xml），覆盖结构 API、工作流、项目、连接、发布权限和 Crew 浏览器界面；前端类型、构建及 912 条翻译校验通过，OpenAPI 类型同步校验通过。测试包括模拟历史重复、团队列表排除、刷新保存、延迟初始加载、390px 横向溢出、版本冲突及非法导航。独立复核发现的导航发布约束和加载竞态已修复。

本地 8876 预览已重启加载新接口，实测 dfsa 仅一份当前可编辑草稿，原两家店及 dfsa 三份方案仍在。不调用模型 API、不产生本轮模型费用；保存结构不会发布真实网站。
