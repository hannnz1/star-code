# MUSE 商家任务看板：功能核对与 UI 调整

最新交付以 [任务看板最新对齐报告](task-board-final-alignment-2026-10-05.md) 为准；本文件保留此前批次的历史记录。

核对日期：2026-10-05。参考：[Replit Agent Task Board](https://docs.replit.com/features/agent/task-board)、[Task Lifecycle](https://docs.replit.com/features/agent/task-lifecycle)。这是产品能力对照，不表示 MUSE 与 Replit 的运行或隔离机制相同。

## 先核对功能

| Replit Task Board 能力 | MUSE 商家版现状 | 判定与处理 |
| --- | --- | --- |
| Draft：保存计划、修改后再启动 | 新增持久草稿、固定五步流程、版本校验、归档/恢复和明确启动；草稿不会创建模型任务 | 已实现商家版草稿。启动时原子创建现有三角色工作流；资料版本变化时拒绝启动，需修改草稿。 |
| Active：后台执行和排队 | 三角色任务复用原任务队列，计划有 `PLANNING`、`BUILDING`、`VERIFYING`、`PUBLISHING` 等状态 | 已具备；看板汇总计划与角色步骤，原任务页保留执行日志、审批和取消。 |
| Ready：审查测试、预览、代码差异 | 有 `REVIEW_REQUIRED`、验证任务六阶段、站点截图、主题代码差异、发布审查；详情新增跨角色成果、预览证据和目标环境摘要 | 已有商家审查主路径。预览和发布目标按计划版本只读加载，版本不一致会提示；具体批准仍以完整发布审查为准。 |
| Apply changes：隔离副本合并主项目 | 各计划保留独立静态主题草稿与封存成果；新增本地项目代码基线、三方文件比较、明确审查后整合，后续任务沿用基线 | 商家静态主题范围已实现。不同文件可合并；同一文件不重叠行可合并，重叠修改和边界插入拒绝整合并列出冲突，不做 Agent 自动冲突修复。代码整合与 WordPress 远端发布是两个独立操作。 |
| Done：已应用、归档、取消的历史 | 已结束计划可单项或批量归档/恢复，归档元数据独立于执行版本；默认隐藏归档，可筛选历史；草稿可归档/恢复 | 已实现商家历史管理。批量计划归档原子校验；任一项过期整批拒绝，成果与审批不变。 |
| 搜索、筛选和任务详情 | 搜索、业务类型/归档筛选、批量草稿及计划管理、卡片操作菜单、角色日志直达；建站完成后提供新品草稿入口 | 已接通；后续建议已按计划状态、错误码和代码冲突生成，并保存来源关联草稿；尚无模型自由推荐和建议批量启动。 |
| 依赖队列、并发隔离 | 三角色依赖展示、前置等待说明；各计划代码独立，整合检查共同起点、当前基线和候选成果 | 静态主题文件隔离与冲突检测已具备。尚无完整应用运行环境复制；Docker 实际隔离仍需 Linux 环境验收。 |

## 本轮 UI 交付

1. 团队任务区域新增“草稿、进行中、待处理、已结束”四列；从真实计划状态映射，不新造后台状态。
2. 卡片展示业务类型、计划编号、版本、下一步及已完成角色步骤；可搜索任务编号/标题/角色任务编号，并筛选业务类型。
3. 点击卡片只展示该计划详情。草稿可修改、归档、恢复和启动；已启动的角色任务可打开原任务页查看日志、审批和结果。
4. 保留原店铺连接、任务创建、验证、预览、代码差异和发布审查入口；看板刷新只读，原“刷新团队状态”才触发状态推进。
5. 从导航进入集中任务看板后，常见桌面四列、平板两列、手机单列；店铺概览中的内嵌看板保留两列。明确“草稿不会调用模型”“已结束不等于已发布”。

本轮测试覆盖和界面截图见 [验收记录](task-board-alignment-validation-2026-10-05.md)。

## 后续功能顺序

1. **真实隔离与发布验收**：静态主题整合不是完整运行环境复制。继续使用独立 Linux/Docker 环境验证编码边界、购买流程和实际发布，不以本机 API 或浏览器测试代替。
2. **冲突处理深化**：同文件不重叠行自动合并已有封存回归证据；重叠行和边界插入仍拒绝并保留双方成果，已提供按冲突文件生成修复草稿，但尚未自动执行修复。最新逐项判定见 [证据报告](task-board-alignment-evidence-2026-10-05.md)。
3. **后续建议深化**：证据规则生成多项建议已完成；继续补充模型推荐、跨计划业务依赖和并发容量提示。自动批准或自动发布会改变现有商家审查边界，本版不启用。

本轮回归还修复了审查摘要与验证面板重复 React key 导致的重复渲染；浏览器测试要求每个选中计划仅有一份审查摘要。统一审查摘要现可逐文件展开差异，读取真实封存清单，并显示验证错误码。计划或项目版本变化后，旧证据不会覆盖新计划的展示。

验收以项目现有浏览器和 API 测试为准。完整站点发布与 Linux/Docker 隔离环境的实测仍应使用独立环境，不能由任务看板 UI 替代。
