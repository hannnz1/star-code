## 本轮修复

1. 新安装 WooCommerce 自动生成的 shop/cart/checkout 与建站计划保留 slug 冲突。仅在全新、空数据库初始化时，将这三页保留为带专用前缀的草稿；检查整个集合后再写入。既有商家页面仍禁止覆盖。
2. 完整主题部署缺少私有包存储，且 Linux 原子目录切换不能跨挂载点。测试副本使用同一卷的 `site` 子目录作为 Apache 文档根，整卷另挂载到受信任的 `/var/muse-volume`；包日志位于其 `packages` 私有目录。部署通过整卷挂载操作主题目录，设备号和 inode 必须与当前主题一致，拒绝其他目录和符号链接。不会把包目录映射到 Apache。
3. 最终独立检查原先仍校验初始主题，误拒绝已正常部署的商家主题。固定 WooCommerce、Connector 和安全插件继续按原始安装摘要逐文件读回；主题按经过封存、归属和不可变代码校验的本次 CodingArtifact 逐文件读回。普通副本 verify 不传封存产物时仍校验全部初始资产。该参数是内部通道，未增加公共 API 或 Agent 权限。
4. 用户任务目标原先没有提供给子 Agent。新任务将原始目标保存在持久 commerce 绑定中；角色读取上下文时从根任务数据库记录取得目标。旧任务没有此字段时返回 null，不猜测目标。现有角色工具、审批和发布限制保持生效。
5. 固定初始化辅助容器中断后必须可识别和清理。恢复检查核对镜像摘要、固定 PHP 命令、原始环境、网络、权限、资源上限和唯一所属卷；拒绝被修改的辅助容器。CLI 镜像的隐式 `/var/www/html` VOLUME 原先生成匿名卷；现在显式受限 tmpfs 覆盖。真实未启动辅助容器恢复返回 `site_ready=false`，清理返回 CLEANED，没有执行根权限代码。旧探针残留先证明匿名卷仅由该未启动测试容器独占后清理，没有全局 prune。
6. 预发布包含串行 CMS 写入和独立读回，不适合与单阶段检查共用 180 秒上限。默认仅 staging 改为 600 秒，其余阶段保持 180 秒；显式测试时限仍受 1800 秒限制。未知结果栅栏、禁止盲目重发及原授权期限不变。run-16 在第 12 个预发布操作处中断，保留失败并清理；run-18 上新预发布实际 196.798 秒，证明有界分阶段时限的必要性。
