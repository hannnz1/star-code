# 本轮商家功能开发预览

2026-10-06 更新：固定平台的真实 Linux 隔离、完整建站及真实模型小样本已有证据；生产商家和人工体验仍未验收。最新状态见 [完整对齐续接](full-alignment-continuation-2026-10-06.md)。历史测试记录不能作为当前部署授权。

当前可用：保存商家项目、生成七类页面的结构草稿、校验并持久保存 CSV 商品草稿和本地图片；通过登记连接读取店铺上下文；资料齐备时创建店长、网站开发、商品内容的三角色准备任务。网站开发可编辑固定静态主题并封存准确代码包，工作台展示实际差异和代码版本。**代码准备不等于网站验收，文件校验不等于已上新**。团队卡片显示真实持久任务 ID、状态和成果哈希。

开发位置：`outputs/muse-next`，分支 `muse-integration`。本轮尚未同步到桌面的旧 `star code` 文件夹，尚未推送 GitHub。

## 本地启动

在这个 Python 交付目录执行 PowerShell 命令；沿用现有模型配置，不在下面命令填写密钥。

```powershell
npm.cmd --prefix frontend run build
.\.venv\Scripts\python.exe -m muse api --config 'C:/Users/Administrator/Desktop/project/star code/config.yaml' --data-dir './work/commerce-preview-state' --port 8876
```

以上从原配置读取模型设置，但只启动 API，不启动付费任务 Worker。在另一个终端运行 `.\.venv\Scripts\python.exe -m muse token --data-dir './work/commerce-preview-state'`，仅在本机将显示的令牌粘贴进 `http://127.0.0.1:8876` 登录框，不贴入文档或聊天。登录后默认进入商家概览，左侧可打开「网站」「商品」「团队任务」和「设置」。完整启动器与原能力使用见 [MUSE 使用指南](../../README.md)。如果正在运行的是旧进程，需要从本开发目录重新启动才会加载新 API。

1. 填写品牌名称、工作区、语言、币种、受众与风格，保存项目。
2. 点击「生成结构草稿」，查看首页/商店/商品详情/购物车/结账/关于/联系七类页面及待确认设置。计划为 NEEDS_INPUT，无模型任务、预览或发布。
3. 从 `tests/fixtures/commerce/new-products.csv` 读取或粘贴商品 CSV。项目币种设置 USD；点击「校验并保存草稿」。CSV 首行和顺序固定；image_names 暂留空。
4. 修正逐行错误后再次提交；正确结果显示精确价格和库存。重复网络请求保持同一记录。刷新后重新打开项目可看到已保存方案和草稿。
5. 点击「开发空间」继续使用原编程、研究和资料整理；这些入口不需要店铺。「偏好与记忆」在设置中。

## 团队任务看板

进入商家项目后，打开「团队任务」。草稿、进行中、待审查、已结束四列显示真实计划状态；可按标题或编号搜索，按建站/新品及需要处理/待审查/执行排队/已结束筛选。缺资料、受阻和待核对任务保留在进行中并提示下一步。点击卡片查看角色步骤、执行日志入口和审查证据。「刷新看板」只读取状态；详情中的「刷新团队状态」才推进工作流。

点击看板「新建任务」打开创建窗口，在「三角色任务准备」填写目标后可先点「保存任务草稿」，检查固定步骤并修改；草稿不会调用模型。关闭窗口会保留本次页面中的输入，再次打开可以继续编辑；刷新网页前需要保存草稿。启动草稿会重新校验项目版本和店铺上下文，然后创建真实任务并产生模型费用。草稿可归档和恢复；勾选多份草稿可以批量归档。已启动的计划可以重命名显示标题，原计划版本和审批绑定不因此改变。

已结束计划也可以单项或批量归档、恢复；默认显示未归档记录，在「历史」选择已归档或全部记录可找回。计划批量操作会检查全部版本，发生冲突时整批拒绝。卡片右侧菜单提供详情、重命名、代码审查和状态允许的取消/归档入口。

点击任务卡片打开详情侧栏，按「任务进度」「成果审查」「后续任务」切换。「成果审查」集中提供审查概览、代码差异与整合、页面预览、验证结果和发布审查；「成果与审查清单」可只读查看角色成果、验证状态、截图和目标环境。缺失或版本不一致的证据会标明，不能将截图检查视为真实店铺验证。建站完成后可预填新品上线草稿，仍需选择商品批次、检查内容并显式启动。后续建议在点击「批量管理建议」后显示选择框，可一起保存为草稿。发布操作继续使用单独的商家审查和确认流程；离开发布面板停止后续步骤，已提交步骤仍需核对回执。

窗口内部也提供中文 / English 切换，商家目标和商品资料保持原文。Escape 或「返回看板」关闭窗口并将键盘焦点恢复到打开它的按钮；页签支持左右方向键及 Home/End。任务看板下的「店铺连接」单独打开连接与上下文窗口。

封存主题后，在「项目代码整合」读取审查，核对拟整合差异并勾选确认，才能更新本地项目代码基线。不同文件的并行修改可组合；同一文件的不重叠行修改也可组合；重叠修改或有歧义的插入拒绝整合，显示冲突文件，保留各计划原成果。新任务默认沿用已整合基线；也可显式选择已保存主题。代码基线更新后，原草稿须保存新版本再启动，避免悄悄改用不同起点。代码整合不改变原计划成果、不获取站点发布许可。

## 保存项目资料

打开商家项目，在「保存项目资料」点击「下载项目资料」。无图为格式 1 ZIP；有当前商品草稿引用图片时为格式 2，增加实际净化图片字节和 media.json。包包含品牌需求、建站计划历史、当前商品草稿和匹配来源的主题包；有封存代码时保存其准确字节，不用初始模板替代开发修改。manifest 提供 SHA-256 和大小，总包上限 16 MiB。下载过程不调用模型、不访问店铺、不修改项目。

项目版本已变化时拒绝导出旧版本，请重新打开项目后下载。旧版本商品导入不作为当前商品草稿导出；历史计划保持自身状态，不能当作已通过的发布方案。导出不读取凭据、客户、订单、任务提示或执行许可；用户自己填写的私人文本会保留，分享前请检查。

这是离线资料交接，不是一键迁移或整店备份。工作台已支持恢复为新商家项目，见下文；旧连接、批准和客户订单不随包恢复。新目标仍需重新确认来源、SKU 冲突、staging、购买验证及批准。固定平台已有 Linux 测试证据，默认部署锁仍未放行生产。

## 店铺连接与团队准备

没有独立连接服务时，仍可做上述离线准备；连接/刷新返回明确阻塞，不能用未验证版本清单绕过。连接器配置与隔离要求见 [connector.md](connector.md)。真实 Linux 测试站建站、购买、独立检查和发布读回已通过；生产商家目标与人工验收仍未执行。

主程序配置可以在现有 providers 配置旁增加以下对象，模型设置保持原样。这里只填写服务地址、环境变量名称和版本文件路径；WordPress Application Password 属于独立连接器，不进入主程序配置或 Agent 工作区。

```yaml
commerce_connector:
  service_url: https://已配置的连接服务地址
  token_env: MUSE_COMMERCE_CONNECTOR_TOKEN
  versions_lock_path: deploy/commerce/versions.lock.json
```

service_url 必须 HTTPS，开发仅允许 loopback HTTP；版本文件路径相对本配置文件。Connector 服务身份从指定环境变量读取；正式环境需要已验证的版本与镜像 digest。本仓库候选清单仍 `verified: false`，这不是可直接连接的示例部署。

1. 在「店铺连接与上下文」填写服务中预先登记、属于本项目的 connection ID，点击绑定。页面不接受任意店铺 URL 或 WordPress 凭据。
2. 刷新 staging 上下文，检查页面/商品数量、平台版本和快照哈希。读取失败保留原快照。品牌、连接或有效快照变化会使旧计划 STALE 并取消旧团队；需重新打开项目、重新校验旧版本 CSV。
3. 选择建站准备或新品准备。新品准备必须选择当前项目版本的商品批次。填写目标和整个团队共享的模型请求上限。缺少政策、运输、付款等已知事实时仅保存 NEEDS_INPUT 计划，**不创建模型任务或预算**；页面列出待补字段。
   运输/付款须由店铺管理员在 WordPress「设置 → MUSE 店铺准备」确认；先配置 WooCommerce 运输和付款方式，再保存两个确认项，回 MUSE 刷新上下文。连接服务账号无权确认。任一类方式全部停用后，对应准备状态自动变为未就绪；商家确认不代表购买测试通过或已批准发布。
4. 只有 API 服务时，资料齐备的根任务停在 QUEUED，不会调用模型。启动原 Worker 后才执行并消耗原模型 API 额度。共享请求上限不是美元额度，也不自动采用之前的 benchmark 费用授权。
5. 在原任务列表处理技术审批/待回答问题。回到团队卡片点击「刷新团队状态」，查看真实子任务和成果。模型故障时恢复的是原任务和原预算，不另建根任务，不静默切换模型；角色资源固定，不支持普通 reload 操作。
6. 新创建的角色任务可用 read_theme_file、write_theme_file、show_theme_diff、seal_theme_code 编辑固定主题静态文件并封存真实 Git 代码版本。PHP 固定不变，没有宿主 Shell 权限；编辑后未封存不能完成代码准备。旧冻结任务不会自动扩充工具上限。
7. 代码封存后刷新团队状态，点击「查看主题代码差异」。此时 site_verified=false、published=false；即使三角色成果齐备，缺少真实隔离/站点验证仍会 BLOCKED，不生成发布批准。需确认的新事实进入 NEEDS_INPUT，格式错误仅允许一次修正。

可自行启用 Worker 的命令如下。这会执行该 data-dir 中已排队的任务并产生实际模型费用。真实模型评测在独立合成项目内执行，未使用这里的预览数据库。

```powershell
.\.venv\Scripts\python.exe -m muse worker --config 'C:/Users/Administrator/Desktop/project/star code/config.yaml' --data-dir './work/commerce-preview-state'
```

原技术审批不等于商家发布批准。公开工作台已增加「查看发布审查」：有可信验证来源后，可核对目标、商品、图片、代码版本和固定步骤，勾选确认并批准，之后显式发布下一步或只读对账。没有可信来源时不会生成审查；缺隔离部署时不能发布。固定连接器插件已有九类受限操作，临时 CMS 功能证据仍不能代表完整团队/真实 Linux 验收。独立服务启用方法见 [连接器说明](connector.md)。

CSV 限 1 MiB、1–20 件简单商品。SKU trim+casefold 去重，价格保留 Decimal，拒绝公式/非整数库存/错误币种。当前 API 校验资料，**未检查真实店铺已有 SKU**。工作台可上传 PNG/JPEG/WebP，解码校验后清除附带元数据并保存；每文件 10 MiB、每项目 100 张/100 MiB、每件商品最多 5 张。CSV image_names 使用已勾选图片文件名，多张用 | 分隔；图片引用不能跨项目。上传到 WordPress 尚待审查发布集成，不代表上新完成。内容改写与新认证/功效需后续商家确认流程，不以模型自报来源放行。

## 恢复并继续项目开发

1. 在商家工作台点击「新建商家项目」，在「恢复项目资料」选择目标工作区和已导出的 MUSE 项目 ZIP，点击「恢复为新商家项目」。文件最大 16 MiB；失败不会留下部分项目。
2. 恢复后核对品牌需求、商品草稿、图片。新项目版本从 1 开始，不包含旧店铺连接、客户、订单、任务、快照或发布批准。
3. 如资料中有主题代码，「三角色任务准备」会出现「主题代码起点」。先下载核对，再选择要沿用的恢复主题；不选择时生成初始主题。所有主题来源均标记为尚未通过新店铺验证。
4. 配置新的 staging 连接并刷新上下文。启动新任务会使用原模型配置并产生实际 API 费用；网站开发沿用所选固定静态文件，修改后需重新封存和验证，不复用旧代码许可。
5. 公开恢复操作仅保存本地资料，没有部署或发布副作用。连接或快照改变项目版本后，重新校验并确认商品批次，再启动新计划。已接通的后台验证可生成新的预览、购买证据及审查报告；正式发布仍需本项目单独批准。恢复本身不代表已迁移上线。

相同恢复请求和准确 ZIP 重试不会重复创建；成功后重新选择文件发起新的恢复会创建另一个独立项目。项目 ZIP 是用户提供的数据，校验和仅验证完整性，不证明商家事实或部署验收。

## 后台验收入口

连接服务需在完成版本锁验证的独立 Linux/Docker 宿主显式启用参考站和验证功能，配置见 reference-environments.md。本仓库默认锁仍为 verified:false，当前 Windows 工作台不能直接执行 Linux 部署验收。

团队任务代码封存、来源齐备后，在「店铺验证」点击开始后台验证；查看隔离环境、封存来源、部署预览、购买流程、页面截图、商品事实六阶段进度。刷新只读。中断先点只读核对，预览剩余步骤只有在无未知操作且原许可未过期时才能明确继续。错误、取消或过期不会自动部署或重新下单。

空商品/零库存建站通过隐藏测试商品验证购买，预览标注“测试商品（不会发布）”。它不会进入商家正式发布清单。报告就绪后查看发布审查、核对目标与差异，另行批准及显式发布。当前实现与尚缺真实验收见 acceptance-evidence-2026-10-02.md。

### 后续任务建议

团队计划详情点击「读取后续建议」，核对实际状态、错误码或代码冲突证据，再保存建议草稿。草稿保留来源计划与版本；先修改商品批次等资料，明确启动后才进入模型队列。建议采用商家规则，不代表任意项目的 AI 推荐；来源记录也不等于跨计划执行依赖。过期建议须重新读取。详见 [后续建议验收](task-board-follow-ups-validation-2026-10-05.md)。

### 任务排队与一次性自动应用

已保存草稿可在看板选择多项并批准启动；容量满或前置业务计划未完成时显示排队。只有 Worker 能放行，刷新只读。取消排队会归档且清除一次性授权，恢复后须重新批准。配置 `commerce.max_active_plans` 控制每个项目并发上限（默认 2）。

任务卡片菜单或详情可设置一次性自动应用本地静态主题（24 小时有效），不批准真实店铺发布。模型建议按钮使用当前模型、最多一次请求；先核对提示的摘要外发范围和成本，再保存或批量保存建议草稿。详见 [最新对齐报告](task-board-final-alignment-2026-10-05.md)。
# 本地可视化编辑入口（2026-10-06 开发版）

1. 在工作台选择店铺，打开“网站”，点击“准备或更新编辑草稿”。
2. 左侧选择/添加首屏、分类入口、商品推荐、品牌介绍或 FAQ；中间为结构预览，右侧编辑内容。全站颜色和字体在左侧调整。
3. 点击“保存网站草稿”，刷新后核对内容。未保存时离开会请求确认；取消后保留输入。多窗口发生版本冲突时可导出输入，或明确放弃后“重新读取已保存版本”。
4. 在“商品”上传素材，新素材会直接出现在商品表单和首页图片选择器中；填写 SKU、名称、币种对应价格、库存和图片，保存为新资料版本，不会直接上架。
5. 首页 AI 建议须先保存当前修改，再针对选中区块提出要求。等待建议、检查差异，选择接受或拒绝。正常使用须启动原有 Worker，调用沿用的模型配置会产生 API 费用。
6. 真正的网站预览和发布须通过团队任务、隔离运行、独立购买验证及商家审查。中间的结构画布不表示网站已上线；域名、商家付款及正式配送设置仍需实际配置和验收。

当前分类区块支持内容编辑，**分类目标导航还未完成**；不要将任意分类地址当作已验证入口。完整边界与测试证据见 [可视化编辑验收记录](visual-store-editor-acceptance-2026-10-06.md)。
