# 第六批审查及处理

本批交付 P7 的内部持久审批基础，尚未开放批准或发布接口。审查仅进行一轮，五项 Important 在一次修复阶段处理，并补充回归验证；未重新派发审查。

1. 首次批准与执行前读取都重新核对变更集摘要、验证结果及来源；审查保存时固定报告摘要，报告证据被修改也拒绝。
2. 数据库到期列必须与原批准的到期时间一致，不能通过修改列值延长批准。状态列仍用于读取当前撤销状态。
3. 撤销和到期刷新只将仍匹配原批准、尚处 APPROVED 的计划恢复为 REVIEW_REQUIRED；不覆盖后来修改或执行中的计划。
4. 主题包代码版本、内容摘要、包摘要必须与计划、报告和变更集一致。
5. 来源摘要必须为完整 SHA-256，存在的代码版本必须为完整 40 位提交标识，拒绝占位文本。

28 项审批模块测试通过，包括重启持久化、并发重复批准、固定 30 分钟有效期、失效来源、撤销、到期、主题包正反例、修改报告证据，以及保留新计划状态。测试使用本地 SQLite 和人工构造的验证报告，不证明真实网站检查已经执行。

边界：到期状态由 provider、approve 或显式 expire_due 刷新；尚无后台定时刷新或 UI 接入。实际 P6 验证器、主题来源摘要的统一生成、失效后重新审查流程、PHP 原子写端和发布闭环仍待实现。数据库摘要一致性不能替代 OS 隔离，也不能认证物理数据库被整体改写的情况。
