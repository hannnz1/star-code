# 分类导航与配送规则：已批准编辑计划的实施补充

本文件细化原 T4/T6，不重新授权生产发布或调用模型。

## 顺序与边界

1. 配送草稿：复用当前结构草稿及项目/草稿版本，固定运费和可选免运门槛使用精确金额。最多 10 个配送区域，每区域最多 20 个 ISO 国家代码；区域不能重叠。保存不写 WordPress，不标记配置/验证通过。
2. 分类导航：保留原页面导航序列化；新增明确 collection 类型的引用，分类名称从项目商品来源取得，不能填任意 URL。第一版的分类来自本次建站商品批次；已有未进入该批次的分类需导入商品来源，不能直接相信远程 ID。分类删除或事实变更必须阻断发布。二级导航不开放。
3. 编译和发布：新能力使用独立版本的商家/预览授权，保留旧 v3/v4/v5/v6。分类导航在商品分类真实创建后绑定平台分类；新配送操作只管理本项目创建的地区/方式，不删除外部商家设置。单次发送出现 UNKNOWN 时只读回，不重发。
4. 同源验证：封存蓝图、配送和商品事实生成预览；独立核对导航目标、分类与配送规则，测试低于/等于/高于免运门槛的实际结账结果。
5. UI：网站栏目提供配送表单、分类导航名称与排序；中文/英文、390/1440px，失败保留输入，切店不接收旧响应。
6. 验收：先合同/API RED→GREEN，再 Python/PHP 协议与旧流程回归，再真实一次性 Linux WordPress 验证，最后人工验收。

## 关键兼容决策

- 老页面导航不新增默认字段，避免改写封存来源摘要。
- 配送草稿保存到当前结构草稿 required_settings，通过原内容摘要/版本绑定进入建站，不在通用 Agent 工具中提供任意远程写入口。
- 建站所选商品批次必须提供分类目标；缺少或删除目标明确报错，不退化成商店首页或猜测链接。
- 配送规则仅固定费率及金额免运；税务、承运商报价、订单履约、正式支付连接不包含在本轮。
