# MUSE 完整替代 Java：收尾与发布工作计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 默认在当前会话执行，不自动创建独立任务或委派子代理。

**Goal:** 将当前 Python MUSE 候选版完成可靠性检查、原指标复测、独立 Windows 验收及可回滚交付，形成有证据支持的 Java 运行时替代结论。

**Architecture:** 保持现有 Python Agent、SQLite 持久化任务、API/Worker、网页与终端入口。主要工作是验证边界、修复已确认缺陷、补齐实验和制作发行包；不再更换核心架构。用同一冻结候选提交串联测试、Benchmark 和安装包。

**Tech Stack:** Python >=3.12、FastAPI、SQLite/SQLAlchemy、Textual、React、Playwright、MCP、pytest；原 StarCode 模型配置。

**Spec:** `outputs/MUSE项目修改计划.md`、`outputs/MUSE基于mewcode-python的替代方案.md`、`outputs/MUSE测试与Benchmark标准.md`；本仓库 `docs/retention-and-mcp-loading.md`、`docs/java-behavior-audit.md`、`docs/clean-windows-acceptance.md`。前三项相对于会话工作区，后三项相对于 muse-next 仓库。

**状态：** 计划文档，尚未开始执行下列收尾任务。日期：2026-09-27。检查点数字属于当前证据，排期属于估计。

## Global Constraints

- 沿用原 StarCode 服务、模型和凭据来源；不为提高成绩临时换模型或预算。
- 默认最多 40 模型轮次、100 工具调用、900 秒累计活动时间；需要不同实验预算时必须预先登记，不能在看到失败后改口径。
- 保留原 Java 工程、所有历史失败和原交付包；不得直接删除或覆盖。
- 新代码、配置、提示或预算变化后，形成新候选版本；正式结果不能跨版本拼接。
- 普通工程测试不调用付费模型；真实实验单独运行并记录全部用量，未知费用为 null。
- 使用冻结合成资料；真实项目文件外发仅限已获授权范围，不能把旧授权扩展到整仓库。
- 用户已确认独立 Windows 环境存在，稍后提供信息；不重复询问，不把缺少环境记为通过。
- 发布物的安装、启动和核心功能不得依赖 Java/JVM/Gradle；这不意味着禁止助手处理 Java 源码项目。
- 原来源主许可证核实前只做本地候选交付，不公开分发或推送。
- 本计划不纳入 OCR、多用户、云端部署、移动端或新模型切换。
