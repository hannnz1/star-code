# MUSE / StarCode Python 功能升级 Spec

文档编号：SPEC-MUSE-UPGRADE-001
版本：1.0
日期：2026-09-28
状态：已按用户授权实施；本文定义需求，逐项开发和验收状态见 `docs/muse-upgrade-status-2026-09-28.md`，不以本文替代验收证据。
依据：`docs/mewcode-baseline-feature-audit-2026-09-28.md`。
基线：桌面 Python mewcode v0.2.0；升级对象：当前 Python MUSE v0.3.0rc8 的公开运行入口。

## 1. 目标与约束

### 1.1 用户目标

以 Python mewcode 的实际可达功能为基线，补齐当前 StarCode/MUSE 的功能缺口，使 Python 版本能够继续承担编程助手和个人助手工作，并支持后续 Java 替代验收。

已明确的约束：

- 使用 Python 核心；保留编程能力、网页研究、资料整理和后台任务。
- 沿用用户选定的原 StarCode 模型配置。子 Agent、Skill、记忆维护不能自行切换模型或凭据。
- 先完成开发和自动验证，需人工操作的 benchmark 留给用户最后验收。
- 真实模型测试按获准预算执行；既有 5 美元上限不能被当成新的无限测试授权。

本 Spec 作出的设计选择：保留 MUSE 的 SQLite、API/Worker、持久化团队和工作区边界；补齐功能，而不恢复两套并行运行时。自动记忆能力通过可配置的持久化维护流程实现，不直接启用旧私有入口。

### 1.2 完成含义

分开记录三种状态：

1. **功能开发完成**：本文对应需求有公开入口、有自动验证证据，兼容变化有文档和迁移策略。
2. **平台验收完成**：相应 Windows/Linux/macOS 环境的真实验证通过。
3. **能力指标已验证**：真实模型、正式 benchmark 和人工复核达到预先定义的标准。

单元测试通过不能推出第三种状态。保留旧模块、调用模型成功、子任务返回文字，都不能独立证明任务完成。

## 2. 方案选择与升级范围

| 方案 | 特点 | 决策 |
|---|---|---|
| 在当前 MUSE 服务补齐基线能力 | 共享权限、预算、任务状态和证据；需要明确处理兼容差异 | 采用 |
| 恢复旧 mewcode App 作为第二运行时 | 初期可快速暴露旧功能，但会产生两套记忆、权限和后台生命周期 | 不采用 |
| 只修 worktree，改写介绍以删除其余能力 | 工作量小，但不满足本次功能升级目的 | 不采用 |

本次涵盖：worktree 稳定性、thinking 协议、权限模式、自动记忆、文件工具、协调者模式、显式可信指令/角色来源、Skill 快捷执行、协作追踪和可选 OS 沙箱。

已有编程、研究、资料、后台任务、MCP、Hooks、团队消息/任务板和上下文召回必须作为回归范围保留。

不纳入本次：新建 Java 功能、新的 Windows 内核沙箱、任意 Markdown 命令系统、批量替换扩展、tmux/iTerm2 后端、角色自动换模型、无限制 bypassPermissions。基线未证实可达的占位功能不作为兼容义务。

这是多个子系统的总 Spec。后续实施计划应按里程碑分拆，每个子系统独立开发和验收，不能将全部需求合成一次不可审查的修改。

## 3. 必须保留与明确改变的契约

| 契约 | 升级决策 |
|---|---|
| SQLite 权威状态 | 保留。会话和记忆的权威存储不切回 JSONL；可导出脱敏 JSONL，但不能据此声称权威存储是 JSONL |
| 所选模型与凭据 | 保留。记忆、角色、Skill 均使用同一所选 provider；不增加隐式外部服务 |
| 工作区及来源边界 | 保留。全局指令和角色来源必须显式注册，不能恢复无条件扫描用户目录 |
| API/Worker 后台任务 | 保留。客户端关闭或超时后任务继续运行；取消由任务控制协议完成 |
| default / acceptEdits | 恢复不同写入审批语义，详见 U03；这是本次有意修正的行为 |
| bypassPermissions | 不恢复；未知模式必须明确拒绝，不能偷偷降级 |
| 子 Agent 后端 | 保留持久化 Worker 和团队视图，不恢复 --teammate 或窗格权威状态 |
| Plan / Do | 保留不同任务的设计；增加明确的计划来源链接，不能假称为同一会话模式切换 |
| 回退 | 保留文件回退和会话分叉；本轮不实现 files/conversation/both 的联合原子回退 |
| -p / stream-json | 保留当前任务式协议和退出码；记录 schema 版本，不恢复旧 NDJSON 的逐字段兼容 |
| 远程入口 | 保留 loopback API 的默认网络边界，不为了复刻基线自动绑定 0.0.0.0 |

因此最终用语应为“核心功能对齐、已声明兼容变化的 Python 替代版”，不能宣称所有旧 CLI 和内部存储格式逐字兼容。

## 4. 架构与数据流

继续使用以下调用链：

```text
CLI / TUI / Web
  → 同一任务 API → SQLite 任务、策略、检查点
  → Worker → Agent loop → provider adapter
  → 工具注册表 → 权限与来源校验 → 工具执行和持久化回执
  → 子任务 / worktree / 团队整合 / 验证
```

新增自动记忆流：

```text
合格会话快照 → 去重的维护作业 → 提取候选记忆
  → 敏感信息/来源/作用域校验 → 发布项目记忆或保留待确认候选
  → 定期整理版本 → 相关召回 → 标为资料而非指令的模型上下文
```

维护作业不拥有 Shell、文件编辑、MCP 或团队执行工具。维护失败不能将已经完成的编程任务改成失败，但必须有可查询的失败状态和费用记录。

### 4.1 状态扩展

所有以下名称都是拟新增契约，不是对现有实现的描述：

- 任务策略：`permission_mode`、`coordinator_mode`、`policy_version`、有效沙箱策略、可信来源快照。
- 记忆版本：候选/生效/替代/撤回状态、作用域、来源消息、版本号、时间和冲突关系。
- 维护作业：作业种类、来源快照哈希、状态、租约、唯一键、模型用量与重试记录。
- 追踪事件：任务/父任务/工具调用关联、序号、耗时、状态、审批展示事件、脱敏错误。
- provider 内部状态：只保存后续请求必需的协议片段，与公开展示分离。

这些扩展必须采用增量数据库迁移，见第 7 节。

## 5. 功能需求与验收标准

“必须”表示对应里程碑放行条件。“可选”表示用户可以关闭能力，不表示实现可以省略。

### U01 — Windows 长路径 worktree 与协作完成判定（P0）

**问题**：当前深目录下 spawn_worktree 出现 `fatal: '$GIT_DIR' too big`，短目录对照通过。

要求：

1. 支持显式配置独立的短 `managed_root`；审批摘要绑定最终解析的目标路径和准确基准提交。批准后不能换路径执行。
2. 针对源仓库路径、Git 元数据路径、checkout 路径和工作树内文件路径分别检查。仅加 `core.longpaths=true` 或仅缩短目标目录不能作为完成依据。
3. 默认目标为“当前真实项目深度可运行”。无法支持的更深路径必须在产生不完整副作用前返回结构化错误及可操作的配置建议。
4. 保留准确提交、角色限制、父目录未提交内容保护、受审查集成和人工可恢复工作树。不能通过复制私密 ignored 文件或运行仓库 hooks 绕开问题。
5. 需要协作的任务遇到未解决的创建/整合错误时，不得仅凭模型最终文字判定 SUCCEEDED。允许用户显式选择串行降级；降级必须留证据。
6. 既有工作树不自动搬迁或删除；根目录配置变更仅影响新工作树。

验收：

- **AC-U01-01**：当前项目真实路径、短路径、带空格/中文路径均完成创建→子任务读写→Worker 重启→审查→集成→统一验证。
- **AC-U01-02**：加入更深路径压力例；成功或预检明确拒绝均有记录，不能生成“创建失败但父任务成功”的结果。
- **AC-U01-03**：父工作区未提交改动不丢失；失败的工作树可以查阅和恢复；重复执行不重复创建子任务。

影响位置：`src/muse/extensions/worktrees.py`、任务完成检查、配置、worktree 测试。

### U02 — thinking 配置、流式摘要与协议状态（P1）

要求：

1. 保留原 `thinking` 配置字段，并按所选协议和模型能力构造实际请求。能力必须来自明确配置/经测试的适配规则，不能按不可靠名称猜测。
2. thinking=false 不增加显式思考参数；不保证模型内部完全停止推理。
3. thinking=true 在支持的协议中发送相应参数；未知或不支持的组合返回 `UNSUPPORTED_THINKING`，不得默默忽略或换模型。
4. 若服务返回可展示的思考摘要，终端和网页能够显示；服务未提供摘要时明确显示“未返回摘要”。不编造思考内容，不要求服务暴露私有完整推理链。
5. 后续工具轮次需要的签名/opaque 协议块必须正确回传；这些内部片段不进入公共 trace、报告或日志。
6. thinking 的 Token、缓存和费用纳入同一预算；输出预算不足必须明确失败，不执行未完整解析的工具调用。

验收：

- **AC-U02-01**：对 Anthropic、Responses、Chat Completions 用模拟传输断言支持组合的实际 payload、关闭行为和不支持错误。
- **AC-U02-02**：覆盖摘要→工具调用→工具回执→下一轮、混合分片、不完整流和服务错误；完整工具调用只执行一次。
- **AC-U02-03**：获准预算下，对实际选定的 provider 做冒烟；不支持的能力明确标注，不能用模拟测试充当真实服务验证。

影响位置：配置、provider adapters、`ModelEvent`、TUI/Web 事件消费、协议测试。

### U03 — 持久化权限模式（P1）

任务创建 API、-p、TUI、Web 必须传递并持久化同一个权限模式；子任务不得自行放宽。工具风险分类保持为 read/write/execute。

| 模式 | read | 工作区内 write | execute：命令、网络副作用、安装、委派等 |
|---|---|---|---|
| default | 按边界允许 | 逐动作批准 | 逐动作批准 |
| acceptEdits | 按边界允许 | 在该任务工作区内允许 | 逐动作批准 |
| plan | 只读工具可用 | 拒绝 | 拒绝 |

用户/跨项目记忆写入仍使用专门的批准流程，不因 acceptEdits 自动允许。路径拒绝规则优先于模式；接受编辑不授予工作区外文件、密钥文件或 Git 控制文件的访问权。

新增任务默认 default；旧任务采用迁移时记录的既有有效策略，标注 legacy policy，不能静默改变正在执行的任务。`read_only=true` 的旧请求仍映射为 plan；与显式非 plan 模式同时出现时拒绝矛盾请求。新接口以 permission_mode 为准。

模式只可在任务未运行或已暂停时由用户修改；修改增加策略版本，使尚未消费的旧审批失效。审批绑定规范化参数、工作区、模式、策略版本和有效期。Worker 恢复必须使用持久化策略。

验收：

- **AC-U03-01**：同一 write_file 在 default 等待批准，在 acceptEdits 执行，在 plan 拒绝；命令在前两者均需批准。
- **AC-U03-02**：直接 API、CLI、TUI、Web、子任务及重启后的决策一致；计划任务不能借子任务、Skill 或 Hooks 绕过只读限制。
- **AC-U03-03**：模式变更、参数变更、过期、跨任务复用和拒绝后重试均不能复用不匹配授权。
- **AC-U03-04**：记录实际前端审批展示事件。不能为达到 ≤5 次 benchmark 目标而默认放宽执行权限。

影响位置：任务契约/数据库/API、compat_cli、terminal、工具分发、权限、所有执行型扩展。

### U04 — LLM 自动记忆提取（P1）

要求：

1. 增加可配置的项目记忆自动提取能力。升级既有安装时默认关闭；用户在设置中开启并设置维护预算后生效。普通跨会话记忆保存不依赖该开关。
2. 对有新增有效对话的非只读完成任务、压缩前快照创建维护作业；以任务、快照哈希、提取器版本去重。plan/review、取消和失败任务不自动发布记忆；用户可以独立发起明确授权的记忆维护任务。
3. 同时提取稳定偏好/项目事实，排除一次性任务文本和已执行工具权限。每条候选必须有精确来源；不能把模型推断当用户事实。
4. 非敏感、无冲突、有明确用户来源的项目记忆可自动发布；授权来自用户显式开启的项目维护策略，不复用工具执行审批。冲突和不确定候选待用户确认。用户级跨项目记忆必须明确确认，不能自动提升作用域。
5. 密钥、令牌和其他敏感数据不得写入记忆或错误回执；测试夹具必须覆盖伪造密钥和诱导写入。
6. 维护模型与所选模型一致，消费单独设置的维护限额，并计入全局运行费用上限；预算不足记为 BUDGET_EXHAUSTED，不能无限重试。

验收：

- **AC-U04-01**：会话 A 自动提取后关闭/重开，独立会话 B 在正确项目召回；其他项目不出现项目记忆。
- **AC-U04-02**：重复快照、重启和重试只产生一份有效版本；关闭功能后不产生新提取请求。
- **AC-U04-03**：冻结 60 条人工标注片段，记录提取精确率、召回率、冲突处理及敏感信息误存；敏感信息误存和跨项目泄漏必须为 0。其余质量指标报告实测，不预填成功值。

影响位置：memory service、维护作业/Worker、Agent 快照、配置、记忆管理 API/UI。

### U05 — 自动记忆整理与版本管理（P1）

要求：

1. 默认整理触发门槛为距上次成功整理 ≥24 小时，且新增合格会话 ≥5；只有自动维护开关开启、预算可用时触发。
2. 一个项目同一时间只运行一个整理作业；用持久化唯一键和租约保证重启可恢复。
3. 归并重复内容、标注被新事实替代的旧记录、保留来源和版本。冲突没有明确新来源时，不自动删除任一事实。
4. 整理不能变更作用域、访问权限或项目指令；删除采用可审计撤回，不能破坏历史证据。
5. 撤回/删除立即排除后续召回；更新召回索引和检查点缓存，不能让旧摘要继续注入已撤回记忆。

验收：

- **AC-U05-01**：虚拟时间验证阈值前不触发、阈值后只触发一次；无需为单元测试等待 24 小时。
- **AC-U05-02**：重复/更新/冲突/过期夹具的版本关系正确；整理中断后不丢原始记忆。
- **AC-U05-03**：删除后新会话及继续运行任务的下一次记忆投影均不再注入该记录。

### U06 — 相关召回与时效（P1）

要求：

1. 只对生效且可访问的记忆召回；用户级与当前项目候选池分开过滤，再排序。
2. 保留字面检索接口；加入语义选择阶段，使用同一所选模型和有界候选摘要，不新增外部 embedding 服务。
3. 提供确定性本地降级。语义请求不可用或预算不足时返回带 `fallback=true` 的本地结果，不能停止编程主任务。
4. 默认候选上限 100、注入上限 10 条，并受上下文 Token 配额限制。长条目截断和未入选原因可查询。
5. 返回来源、版本、有效/替代状态及时间；明确的较新事实优先，矛盾不能隐藏。召回内容始终标为资料，不具备授权或系统指令效力。

验收：

- **AC-U06-01**：稳定事实、同义问法、最新值、无关干扰、跨项目和撤回夹具均有逐条召回结果。
- **AC-U06-02**：语义服务失败时本地降级可用；费用计入维护预算，不能换模型或静默调用其他服务。
- **AC-U06-03**：同一冻结任务集对比字面/语义策略，报告 top-k 命中与错误注入，不能仅凭一条记忆声称语义召回质量达标。

### U07 — 按行读取与正则搜索（P1）

拟定工具参数：

```json
{"tool":"read_file","arguments":{"path":"src/example.py","offset":0,"limit":2000}}
{"tool":"search_text","arguments":{"path":".","glob":"**/*.py","pattern":"^def\\s+","regex":true,"case_sensitive":true}}
```

契约：

- read_file：offset 为从 0 开始的行偏移；未提供 offset/limit 时保留旧整文件读取行为；进入按行模式时缺省 offset=0、limit=2000。limit 范围 1–10000，返回从 1 开始的原始行号、下一偏移和截断标志。
- search_text：regex 默认 false、case_sensitive 默认 false，保持旧请求的字面匹配语义；regex=true 时 case_sensitive 仍必须按参数生效。
- 非法正则、负 offset、非法 limit 返回 INVALID_ARGUMENTS；超时/超限不得伪装成无匹配。
- 为正则执行设置可强制终止的时间上限：默认单文件 250ms、整次搜索 5s；不能仅依赖协程超时终止阻塞正则。搜索命中和候选文件数限制保持可查询。
- 路径、UTF-8、安全脱敏和 offload 边界继续生效。此项不引入 replace_all。

验收：

- **AC-U07-01**：首行/末行/空文件/越过 EOF/CRLF/UTF-8 BOM 的行号和分页正确；旧调用行为不变。
- **AC-U07-02**：合法/非法正则、大小写、空结果、glob、数量上限和灾难回溯探针结果正确，超时不拖死 Worker。
- **AC-U07-03**：越界、符号链接/junction、敏感目录仍拒绝；深路径和大文件可以有界读取。

影响位置：`src/muse/tools/files.py`、工具 schema、角色别名、工具测试。

### U08 — 协调者模式（P2）

要求：

1. 用户创建任务时可选择 coordinator_mode，持久化并显示有效模式；只读 plan 不允许通过此模式启动可写子任务。
2. 开启后主 Agent 只做分解、读取、委派、消息、审查和受批准的 worktree 集成；移除直接 write_file/edit_file/run_command/verify_command 等代码执行权限。
3. 主 Agent 不能经 Skill、Hooks 或其他工具包装绕过限制。修改、测试由能力受限的子 Agent 完成；根任务负责验证证据完整性。
4. 子 Agent 的工作区、权限、预算和角色必须显式可见；父任务不能将未检查的子文字当最终完成依据。
5. 该模式不保证模型一定选择协作，也不保证速度提高；无委派或失败时应如实记录。

验收：

- **AC-U08-01**：直接和包装的主 Agent 编辑/命令调用均被拒绝；允许读取/委派/审查/受审集成。
- **AC-U08-02**：双子任务跨文件改动、重启、冲突、取消和最终统一验证完整可追踪。
- **AC-U08-03**：重跑既有 checkout/numeric/text 协作场景，区分模型未委派、工具失败、子任务失败、集成失败四类原因。

### U09 — 显式可信指令和角色来源（P2）

要求：

1. 允许用户显式注册 user instruction roots 和 user agent roots；只接受固定来源目录，不把任意文件系统开放给 Agent。
2. 指令顺序：注册用户来源→注册工作区根→工作区内 Git 根/当前目录祖先链→当前目录 local 文件。相同文件去重；后一层覆盖前一层的规则必须在文档中明确。
3. 祖先遍历不能跨出已注册工作区；@ 引用只能进入当前工作区或明确注册的可信指令根，循环/深度/链接边界仍检查。
4. 内置 general/explore/plan/verification 名称保留，不允许用户或项目覆盖。其他同名自定义角色按用户角色→项目角色加载，项目优先；被覆盖的来源仍可查询。
5. 任务创建时保存来源哈希、加载次序和最终角色定义；文件改变不自动覆盖运行中任务，用户 reload 创建新来源版本。
6. 可信来源注册由用户设置完成，模型或项目文件不能自行注册。

验收：

- **AC-U09-01**：用户/项目/嵌套/local 的加载次序、冲突和去重正确；未注册的用户目录不被读入。
- **AC-U09-02**：越界 @、循环、符号链接/junction 和模型要求注册来源均被拒绝。
- **AC-U09-03**：项目角色覆盖用户角色时来源可见；不同模型/bypass 的角色定义继续拒绝；重启复用原快照。

### U10 — Skill 快捷执行（P2）

要求：

1. 保留 /skill NAME 查看信息；新增明确的 `/run-skill NAME [ARGS]` 执行入口。
2. 无冲突时可以注册 `/<skill-name> [ARGS]` 别名。内置命令优先，冲突别名禁用并展示原因；安装 Skill 不能覆盖 /approve 等控制命令。
3. 快捷入口必须转成持久化 Skill 执行请求，通过同一来源哈希、权限、预算和 fork 逻辑。不能只把名称发给模型后假定已执行。
4. 参数按原文传递，不能在终端侧插入 Shell；上下文 recent/full/none 行为和所选模型约束不变。

验收：

- **AC-U10-01**：目录可见、别名冲突、参数转义、来源变更、审批/拒绝均有证据。
- **AC-U10-02**：运行 Skill 与直接工具调用产生同等持久化回执；只读/协调者模式不能被快捷命令绕过。

### U11 — /trace、计划来源与回退说明（P2）

要求：

1. 新增 `/trace [TASK_ID]`，展示根/子任务、工具、审批、worktree、维护作业和验证的关联时间线；/events 继续可用。
2. 可导出脱敏 JSON/JSONL，包含 schema 版本、task/call/parent ID、单调耗时、状态、用量、错误和证据引用。
3. 不导出密钥、访问令牌、私密思考状态或未脱敏原始请求。
4. /do 从已审查计划创建新任务时，记录 plan_task_id、计划内容哈希和用户请求；计划改变后不能冒用旧审查结果。
5. /rewind 帮助明确文件恢复和会话分叉的区别；请求 both 时说明当前不支持，不能执行一半并报告完整恢复。

验收：

- **AC-U11-01**：从模型委派到集成验证的所有事件可关联；重启后可追踪；工具失败明确可见。
- **AC-U11-02**：导出通过密钥/令牌/协议状态探针检查；文件和会话恢复保留现有数据保护行为。
- **AC-U11-03**：计划来源和哈希可复核；旧 NDJSON 协议差异、退出码及取消行为有更新文档。

### U12 — 可选 OS 沙箱（独立平台里程碑）

要求：

1. 为 Linux bwrap、macOS Seatbelt 提供统一的启用/探测/执行接口；沙箱是可选配置，但声明“支持”前必须实测。
2. 增加 off/required 两种明确策略。required 后端不可用或策略无法执行时，禁止启动命令，不可无提示降级为裸执行。
3. /sandbox 只展示能力或提交用户设置变更；正在运行的任务不被模型自行切换策略。策略和 effective backend 存入任务快照。
4. 明确文件、网络、进程边界；只允许工作区、必要运行时和指定临时目录。网络默认拒绝，必要的允许列表由用户配置。
5. Windows 明确标为 OS_SANDBOX_UNSUPPORTED，保留应用工作区限制和进程取消；不把它们称为内核沙箱。
6. 本轮不提供沙箱下的无限制 bypass 模式。沙箱与动作审批共同生效，不以沙箱可用替代授权。

验收：

- **AC-U12-01**：在 Linux 和 macOS 分别用独立真实进程验证工作区外哨兵读写、网络、子进程及越界路径；保存 OS/后端版本。
- **AC-U12-02**：required 的后端缺失/启动失败不执行原命令；关闭后的行为明确；Windows unsupported 有可复现测试。
- **AC-U12-03**：取消能清理受管进程树，且不能误杀非任务进程；攻击探针和正常编程命令都要通过。

无对应测试机时此里程碑记 BLOCKED，不能算成完整基线对齐通过。

### U13 — 已有能力与公共入口回归（全部里程碑）

要求：

1. 公共 mewcode/muse/TUI/Web 都使用同一服务，不重新暴露旧私有运行函数。
2. 编程、网页研究、资料整理、后台恢复、MCP discovery/load/call、Hooks、团队任务板、历史召回都继续可达。
3. 任务预算、租约、取消、审批和工具回执仍保持恢复幂等；不完整模型流不可执行工具。
4. 基线已有但项目暂不保留的契约必须列在文档中，不能从矩阵消失。

验收：

- **AC-U13-01**：保留既有 87 项相关测试并加入新增需求测试；运行受影响集及发布要求的完整离线套件，逐项记录 skip/fail 原因。
- **AC-U13-02**：由公开入口进行四类场景的本地模拟冒烟，不能仅实例化内部类验证。
- **AC-U13-03**：独立干净 Windows、真实符号链接/junction 和人工 benchmark 的既有放行条件不因本 Spec 而取消。

### U14 — 指标测量与最终 benchmark（最后验收）

沿用 `docs/mewcode-resume-benchmark-plan.md` 的冻结、配对、预算与原始证据规则。

| 指标 | 最终测试和标准 | 性质 |
|---|---|---|
| SWE-bench-Live 修复能力 | ≥20 例先导；正式建议 ≥100 例；官方评分，记录有效分母、环境无效例、resolved 和区间 | 不预设虚构通过率；若预算只够先导则只报告先导 |
| MCP 描述 Token | 冻结 100 工具、30 任务×3 轮 FULL/LAZY 配对；描述 Token 降幅 ≥85%，工具选择质量不下降 | 宣传数值门槛，不等同总费用降低 85% |
| 跨会话记忆 | 60 条标注片段，正确作用域、更新和删除；敏感误存/跨项目泄漏 0 | 功能与质量分别记录 |
| 长上下文事实保留 | ≥100 原子事实；100K/200K/300K 和重启后盲问，有正确来源；新版目标 100% | 17%→100% 还需同模型可运行旧版配对 |
| 8 小时耐久 | 3 次独立会话，每次 ≥8 小时15分、≥40 关键事实检查；全部正确、无副作用重放 | 短时压缩测试不能代替；需最终实跑 |
| 权限弹窗 | ≥30 配对会话，平均实际 UI 展示 ≤5，任务质量不下降、未授权操作 0 | 30→5 还需旧版实际约30的对照 |
| 多 Agent 加速 | 12 个可拆分任务及4个串行负对照，各3轮；同模型/总预算/质量，正式集聚合降幅 ≥55%、估计接近60% | 未达时报告实际速度与费用，不阻止如实描述协作功能 |
| OS 沙箱 | U12 各平台真实探针通过 | 只对已验证平台声明支持 |

验收：

- **AC-U14-01**：各组有 manifest、逐例轨迹、评分、费用、源码/夹具哈希及 FAIL/BLOCKED/NOT_RUN；不删除失败分母。
- **AC-U14-02**：worktree 修复后重跑协作组；按工具回执归因，不能再把 Git 创建失败写成模型不会委派。
- **AC-U14-03**：人工复核最后交给用户；在人工及平台门槛未完成时，状态为“开发完成，验收待完成”。未达宣传数值时更新介绍而非伪造结果。

## 6. 配置、接口与可观察性规范

拟新增配置组：

| 配置组 | 关键内容 | 默认/兼容要求 |
|---|---|---|
| worktrees | managed_root | 显式安全短根；不自动迁移旧树 |
| tasks | default_permission_mode | 新任务 default；旧任务固定迁移有效策略 |
| memory | auto_extract、auto_consolidate、maintenance_budget、recall_top_k | 升级安装自动维护关闭；top_k=10；维护有独立预算 |
| instructions/roles | trusted_user_roots | 默认空，用户显式注册 |
| sandbox | policy、backend、network_allowlist | off；required 不允许降级 |
| provider capabilities | 可用 thinking 参数和摘要/内部状态规则 | 与所选 provider 配套，未知启用组合拒绝 |

配置不得包含真实密钥示例。公共设置必须排除密钥、访问令牌、代理凭据和内部协议状态。前端只展示能力、有效配置和原因，不暴露实现内部数据。

新接口字段采用加法演进，固定事件 schema 版本。权限模式、来源和工作树路径必须由服务校验，不能信任客户端或模型发送的“已批准”标志。

长会话配置必须区分 active_seconds、等待时间和墙钟；为 C8 设置有限但足够的活动预算，不能临时去掉所有上限使试验跑完。

## 7. 数据迁移与回退

1. 迁移前备份数据库并核验当前 schema 版本；迁移操作写入审计记录，失败回滚且服务不接收新任务。
2. 旧任务标注有效 legacy 策略，新任务采用 U03；运行中任务不被默认值变化影响。
3. 现有 SQLite 记忆导入新版本表时保留 ID、作用域和来源。无来源字段的记录标注 legacy/manual，不伪造来源。
4. 旧 Markdown 记忆可由用户显式导入；预览去重、敏感检测和作用域后再提交。JSONL 会话导出是互操作格式，不改变权威存储。
5. 整理采用版本和撤回记录；不物理覆盖原始笔记证据。维护失败保留原记录。
6. 旧审批和 worktree 回执保持可查；策略摘要格式升级后未消费审批重新申请，不自动授权。
7. 不承诺旧二进制可直接读新 schema。回退必须停止 Worker、保留升级后证据、恢复迁移前备份并明确提示升级后新增任务不会自动恢复到旧版。

## 8. 验证层级与证据

| 层级 | 工作 | 是否需要 API/人工 |
|---|---|---|
| L1 | schema、策略、记忆版本、工具参数、provider payload 单元测试 | 不需要模型 API |
| L2 | SQLite/Worker/API/TUI 协作与恢复、本地模拟 HTTP/MCP | 不需要收费 API |
| L3 | 当前深路径/独立 Windows/符号链接、Linux/macOS 沙箱 | 需要相应真实环境 |
| L4 | 选定服务冒烟、记忆质量、配对 MCP/多 Agent/SWE/耐久 | 需要真实 API 预算与时间 |
| L5 | benchmark 人工审核、操作体验和发布声明核对 | 用户最后完成 |

每条 AC 至少关联一个测试或人工用例，记录状态、提交、环境、命令、结果和证据路径。离线和真实模型成绩分开。测试报告不得汇总为笼统“全部已验收”。

## 11. 发布与对外表述门槛

- M0–M3/M5 通过，只能写“核心升级已开发，自动验证通过，沙箱/平台/人工/真实指标按报告状态列出”；全部功能开发完成还需 U12 的实现与自动验证。
- U12 未完成，不能写“已有 OS/内核级沙箱支持”；Windows 不能套用 Linux/macOS 的验证结果。
- 用户未完成独立机器和人工门槛，不能写“Java 完全替代版已正式验收”。
- U14 宣传数值未达标或未运行，只写实际指标或不带数字的能力；不得沿用 85%、17→100%、30→5、60% 当默认成绩。
- 最终交付包含升级说明、兼容矩阵、迁移/回退操作、AC 结果、benchmark 原始证据索引和人工待验清单。

本文只定义升级规格。评审通过后再分拆实施计划；本次编写 Spec 不修改产品代码、不调用模型 API、不执行部署或发布。
