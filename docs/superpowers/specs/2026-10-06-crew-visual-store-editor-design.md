# Crew 可视化建站与商家编辑设计

状态：供用户审核的设计建议；2026-10-06。本次交付为计划，不表示功能已实现。

## 目标与定位

Crew — Your AI commerce team。沿用 WordPress + WooCommerce，以建站和新品上线为主流程。商家通过可视化编辑及一个 AI 协调入口完成任务，店长、网站开发、商品内容三个角色执行。通用编程入口保留。

本轮依据用户提供的 Shopify 教程截图借鉴：区块树与预览联动、局部设置、商品表单、导航、移动端预览、保存状态和开店配置。无需迁移 Shopify。

## 已有基础与边界

已核对本地代码：SiteBlueprint.tsx 支持七类页面标题/路径/导航编辑，后端保存版本检查且新工作流使用当前草稿；这还不是区块编辑器。ProductImport/ProductImages、StorePreview、ThemeCode、CodeIntegration、VerificationPanel、MerchantRelease 已有实现。theme.py 存在确定性主题打包及区块白名单，wordpress/muse-storefront 为受控主题。

既有验收文档记录过隔离发布测试；这不说明当前本机环境可运行，也不等同于真实商家生产发布。新编辑器必须重新验证自身生成的产物。上轮 93 项测试仅证明原草稿修复和相关回归。

## 设计决策

1. 采用受控区块编辑器：扩展现有 Crew 主题，不实现任意 HTML 画布，不同时集成多个页面构建器。
2. 首个闭环只编辑首页：首屏、分类入口、商品推荐、图文介绍、FAQ 五种区块。页眉、页脚为全站设置；购物车、结账使用受控交易模板。后续用同一模型支持关于和联系页。
3. 首版商品支持现有单 SKU 合同。复杂变体、订阅、订单履约、多渠道和应用市场不进入本轮。
4. 手动编辑、AI 建议、预览及 WordPress 产物共用版本化页面文档。实际 WooCommerce 商品仍以其后端记录为准，预览不得伪造价格/库存或订单成功。
5. 核心逻辑和 API 继续 Python，现有 React/TypeScript 前端与 WordPress PHP 连接器沿用。

## 页面布局与状态

“网站”保留概览与建站步骤，增加明确的“编辑网站”入口。桌面编辑器顶部显示页面、草稿/预览/发布状态、设备切换、撤销/重做、保存、生成预览。左侧为页面区块树，中间为画布，右侧为当前区块属性及“让 AI 修改此区块”。未选择时显示全站样式。

主操作随阶段变化，不同时突出多个按钮。编辑状态：CLEAN → DIRTY → SAVING → CLEAN；失败保留 DIRTY 与输入；版本冲突进入 CONFLICT，允许复制本地内容和显式重新加载，不自动覆盖。切店、换页、浏览器离开时提示未保存修改。

草稿保存与正式发布分开。没有站点时显示“结构预览”；真实 WordPress 预览显示目标、来源版本、生成时间；已发布状态必须来自发布回执及读回。历史版本只读，恢复会生成新版本。

## 数据和一致性

新增 StoreDesignDocument（schema_version=1）：project_id、project_revision、revision、blueprint_plan_id、blueprint_revision、theme_tokens、home_sections。区块使用稳定 ID、kind、enabled、经过类型校验的 props。最多 20 个首页区块，文本/链接/图片明确限制；不接收脚本、PHP 或任意 CSS。

SectionPatch 只针对 section_id 更新允许字段；添加/删除/排序采用明确操作。媒体引用复用项目媒体库并验证项目归属、内容摘要和可用性。商品引用使用项目商品身份；渲染到 WooCommerce 时按该版本发布绑定解析真实产品 ID。

主题渲染生成 ThemeArtifactBinding：project_revision、blueprint_revision、design_revision、design_digest、product_digest、media_digest、code_revision、artifact_digest。预览和审批绑定此信息。任何相关输入变化都使旧预览/审批过期，不取消正在执行的发布而盲目重发。

人工代码修改通过现有代码集成流程检测冲突。结构化区块管理的主题区域有清晰归属；遇到不兼容代码时阻止自动覆盖并展示差异。不能把任意生成代码重新解释成可信区块。

## 商品、导航和开店准备

商品编辑支持名称、描述、价格、币种、库存、分类和项目图片；状态区分本地草稿、已提交平台草稿、已发布。CSV 为批量入口。AI 不改变未授权商品事实。

导航首期支持排序、页面/分类目标、名称和隐藏；二级导航最多两层，在平台连接器具备可验证支持后开启。商品详情是模板，不能作为固定页面链接。引用已删除分类/媒体时显示可修复错误。

开店清单包括政策、配送、付款、域名和预览验证。每项分别记录配置和验证状态，允许直接跳转修复。配送支持区域、固定运费、免运门槛及示例计算；前端示例计算必须标为预估，真实 WooCommerce 结账为验收依据。付款连接、域名归属及税务决定不能由 AI 假定完成；税务首期只提供已有设置读取和外部配置入口，不自建税率引擎。政策草稿须商家确认。

## AI 行为与费用

选中区块后局部提出修改，返回结构化提案和前后对比；接受时验证原始文档版本，用户修改过该区块则冲突，不自动覆盖。拒绝不改变草稿。所有工具维持现有权限、费用账本和审查约束。演示使用确定性提供者；真实模型验证需要单独的本轮预算，不能挪用此前宠物店 2 美元授权。

## 验收目标

桌面 1440/1280、平板 900、手机 390/360 无横向溢出；中英文标签一致；键盘可编辑和排序。首页文字/图片/链接/排序保存后刷新一致；重复保存和重复接受提案不产生重复结果；跨项目引用被拒绝。

断网、超时、刷新、切店、多标签页版本冲突均不静默覆盖输入。构造 HTML 注入、错误 URL、损坏媒体以及未知 schema 必须拒绝或安全显示。

原结构草稿、通用编程、任务看板、商品导入和发布审查相关回归通过。真实 WordPress 预览与封存产物一致；测试购买、政策导航及商品事实读回通过。无真实测试环境则标记 BLOCKED，不能用静态预览替代。人工验收安排最后。
